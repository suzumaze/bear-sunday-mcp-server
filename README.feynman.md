# BEAR.Sunday MCP Serverを、専門用語なしで説明する

これは、いつものREADMEを読む前の説明です。

難しいものを本当に理解できているか確かめるために、「初めて聞く人にも分かる言葉で
説明してみる」という学び方があります。一般にファインマン・テクニックと呼ばれる方法です。
この文書も同じ考え方で書いています。

## 一言でいうと

**AIに、BEAR.Sundayプロジェクトの地図を渡す道具です。**

AIはPHPの文字を読むことはできます。しかし、文字を読めることと、そのプロジェクトの
決まりを知っていることは別です。

たとえば、コードに次の文字があったとします。

```php
'app://self/user'
```

BEAR.Sundayを知っている人なら、これはただの文字ではなく、User Resourceを指す住所だと
分かります。AIは文字検索だけでも似た場所を探せますが、それが本当にResourceなのか、
どのファイルが正しいのか、LinkやEmbedで何とつながるのかまでは保証できません。

このプロジェクトは、BEAR.Sundayの決まりを使って、その問いに根拠付きで答えます。

## 図書館にたとえると

BEAR.Sundayのプロジェクトを、大きな図書館だと考えてください。

- PHPやSQL、テンプレートのファイルは「本」です。
- `app://self/user`のようなResource URIは「本の住所」です。
- PhpactorのBEAR拡張は、住所や本どうしの関係を知っている「司書」です。
- MCPサーバーは、AIから質問を受けて司書へ渡す「受付」です。
- AIエージェントは、受付に質問する「利用者」です。

```text
AIエージェント
    ↓ 質問する
MCPサーバー（受付）
    ↓ 調べてもらう
Phpactor + BEAR拡張（司書）
    ↓ 読む
保存済みのプロジェクトファイル（本）
```

受付は、自分で答えを発明しません。司書から受け取った結果をAIへ返します。
そのため、エディターとAIが同じBEAR.Sundayの理解を共有できます。

## 何を質問できるのか

たとえば、AIに普通の言葉で次のように頼めます。

```text
このプロジェクトには、どんなResourceがありますか？
app://self/userはどのファイルですか？
このResourceへ向かうLinkとEmbedを探してください。
このSQL名は、どのSQLファイルを指していますか？
存在しないResource URIを静的に探してください。
JSON SchemaとALPSが、どこまで用意されているか教えてください。
```

AIは必要なMCPツールを選び、ファイルへの相対パスや確認した範囲と一緒に結果を返せます。

## 「見つからない」は、すぐに「バグ」という意味ではない

ここは大切です。

JSON SchemaやALPSがないResourceもあります。テストのために、わざと存在しないURIを
書くこともあります。実行時に組み立てられる値は、保存されたコードだけでは決められません。

この道具が返すのは、次のような**確認できた事実**です。

- 指定された場所には見つからなかった。
- 候補が複数あり、一つに決められなかった。
- 値が動的なので、保存されたコードからは分からなかった。
- その種類の検査は、必要な入口がないため行わなかった。

それが問題なのか、意図した設計なのかは、人間とAIがプロジェクトの事情を見て判断します。

## しないこと

このMCPサーバーは、次のことをしません。

- BEAR.Sundayアプリケーションを実行しません。
- ResourceへHTTPリクエストを送りません。
- PHPファイル、SQL、Schema、ALPSを書き換えません。
- 実行して初めて決まる値を想像で補いません。
- 設計が良いか悪いかを採点しません。

保存済みのファイルを読む、読み取り専用の道具です。

## なぜ二つの部品があるのか

「司書」と「受付」を分けると、同じ知識を別の場所でも使えます。

- エディターは、司書へ直接たずねて定義ジャンプや補完に使えます。
- AIは、MCPの受付を通して同じ司書へたずねられます。

BEAR.Sundayの決まりを二か所にコピーしないので、エディターとAIで答えが食い違いにくく
なります。

## 使い始めるまで

PHP 8.2以上とComposerが必要です。次のコマンドは、MCPサーバー、Phpactor、BEAR拡張を
一つの専用ディレクトリへまとめて入れます。

```console
composer create-project --no-dev --prefer-dist \
  suzumaze/bear-sunday-mcp-server \
  /absolute/path/to/bear-sunday-mcp-server \
  '^0.10'
```

このコマンドは、調べたいBEAR.Sundayプロジェクトを変更しません。

次に、利用するAIクライアントへ「このMCPサーバーで、このプロジェクトを調べる」と一度だけ
登録します。Codexなら次の形です。

```console
codex mcp add bear-sunday -- \
  /absolute/path/to/bear-sunday-mcp-server/bin/bear-sunday-mcp \
  --workspace=/absolute/path/to/bear-project
```

詳しい要件、Claude Codeやほかのクライアントへの登録方法、全24ツールの仕様は
[通常のREADME](README.md)にあります。

## 理解できたか確かめる四つの質問

1. MCPサーバー自身が、BEAR.Sundayの規則を全部持っている？  
   **いいえ。** 規則を知るのはPhpactorのBEAR拡張で、MCPはその受付です。
2. 診断が64件あれば、バグが64件ある？  
   **いいえ。** テスト用の不正な値や、静的には解決できない値も含まれ得ます。
3. MCPを使うと、プロジェクトのファイルが自動修正される？  
   **いいえ。** このサーバーは読み取り専用です。
4. AIは文字検索をしなくてよくなる？  
   **いいえ。** 動的な処理など、意味を静的に決められない部分では文字検索とソース確認も使います。

この四つを自分の言葉で説明できれば、このプロジェクトの中心はもう理解できています。
